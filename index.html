Foundational Check: External Cable Bypass

The absolute fastest way to isolate a SPUD communication failure is to bypass the machine's internal routing. Connect your proven 100ft external crossover cable directly from the network port on the desktop PC to the machine control port. If it works, the issue is an internal cable failure. If it fails, proceed to the protocol below.

SPUD / PC-Mill Protocol

Follow these steps in exact order when responding to a SPUD communication error.

Crucial Network Note: SPUD controllers require a crossover cable. A crossover requires pins 1 & 2 to cross with 3 & 6 (Green and Orange pairs swapped).

1

Power Down and Reseat Physical Connections

Power down the machine entirely. Reseat the crossover network cable at the computer network port and at the machine control port. Ensure you are grounded, then remove and carefully re-seat the Flash card into the Mill PC (CPU board).
2

Assign IP Settings in Control Panel

The tech must assign the port and IP settings manually. Open Windows Control Panel -> Network and Sharing Center -> Ethernet Properties. Select Internet Protocol Version 4 (TCP/IPv4) and verify the static IP is assigned correctly. APIPA (169.254.x.x) means failure.
3

Power Up and Ping Test

Turn the machine on. Open Command Prompt and attempt to ping the machine's communication IP address: ping 192.0.0.47. If successful, communication is restored. If it fails, proceed.
4

Verify Windows HOSTS File (Admin)

Navigate to C:\Windows\System32\drivers\etc. Open Notepad as Admin, then open `hosts`. Verify the exact line: 192.0.0.46 PC MILL. Correct if missing or has a # in front.

5
CPU Board Environmental & Hardware Check

Unplug the flash card and re-seat it into the CPU board one more time, then test. If it still fails, inspect the cooling fan on the CPU board. In hot environments, these fans fail, causing the board to overheat and drop communication.
Heatsink / Fan Area
Flash Card / Storage Area
Diagnostic Tip for CPU Overheating: Ask the operator if they normally run an external box fan aimed into the electrical cabinet. If yes, heat failure is likely. Test with a known good CPU. If successful, offer customer a replacement.

Aldebaran Architecture: User vs. Mill Computers

Understanding the dual-PC architecture is critical before troubleshooting.

User Computer (Windows PC)

This is a Windows-based PC that runs the Aldebaran UI. Dual NICs are strictly required (1 integrated into mother board & 1 external network card). One communicates with the facility network, the other exclusively to the Mill.

  • CPU: Intel i5 2.8 GHz or greater
  • OS: Windows 7 64-bit Professional
  • RAM: 8GB Dual Channel or greater
  • Motherboard: Intel P67 B3
  • Power Supply: Ultra-LSP 550 (500 Watt)
  • Video Card: NVIDIA GTS250
  • Hard Drive: Western Digital 5002AALX 500GB SATA 7200rpm
  • DVD Burner: Asus DRW-24B1ST

⚠️ Since this PC is used strictly for the machine control interface, Tarus does not recommend ANY other external software applications be used on it.

Mill Computer (Embedded)

This is an embedded computer running a Real Time Operating System (RTOS) that provides low-level, fast control of machine movements and I/O functions. Constant interaction between the Mill computer and the User computer is maintained via a Proxy service appearing in the Windows System Tray.

Aldebaran / Mill-Proxy Protocol (RMX)

Utilizes standard straight-through Ethernet cables for RMX systems.

1

Power Cycle, Reseat Cable, & Reseat Mill PC Flash Card

Power down the machine and PC. Reseat the standard straight-thru Ethernet cable at the PC's network port and the Aldebaran machine control port. Crucial: Locate the embedded Mill PC and carefully re-seat the Flash card inserted into it before powering back up.
2

Assign IP Settings in Control Panel

The tech must assign the port and IP settings manually. Open Windows Control Panel -> Network and Sharing Center -> Ethernet Properties. Select Internet Protocol Version 4 (TCP/IPv4). Set the IP address to 192.0.0.47 and Subnet mask to 255.255.255.0.
3

Check Proxy Tray Icon & Services

Look for the proxy icon in the Windows system tray. Alternatively, open services.msc and verify Mill-Proxy is Running. Restart if hung.
4

Verify HOSTS File (Administrator Required)

Open Start Menu > Accessories > Right-click Notepad > Run as Administrator. Browse to C:\Windows\System32\drivers\etc and open the `hosts` file. Ensure the following exact line exists: 192.0.0.46 tpimill. Save and exit.

TarusNC / S-Proxy Protocol

Proprietary overlay communicating directly with Siemens Sinumerik 1 architecture.

Important Note: TarusNC does not use the Windows HOSTS file. Communication relies entirely on physical port matching, Windows IPv4 configuration, and Siemens Communication Settings. Do not attempt to modify HOSTS files for S-Proxy issues.

1 Verify Physical Port Initialization

Trace the straight-thru network cable going directly from the Column PC to the NCU plugged into the board inside the cabinet. Ensure connection on Siemens NCU is in the correct port: Service port (X127) or Plant network port (X120).

Next, open Control Panel\Network and Internet\Network Connections. Unplug the network cable from the PC and plug it back in. Watch the screen to make sure the specific network adapter named Machine Control initializes. Because these PCs have multiple network ports, this ensures you are plugged into the correctly configured port.

2 Verify Machine Control IP Address

Right-click the initialized Machine Control adapter and select Properties. Select Internet Protocol Version 4 (TCP/IPv4) and click Properties.

Verify the IP address is configured exactly as 192.168.214.55 with a subnet mask of 255.255.255.0. If this does not currently match, this is a major problem and must be corrected to establish communication.

3 Siemens Communication Settings

Run SINUMERIK_OPERATE_pc.exe as Administrator (Select Standard ONE NCU and Complete setup).

Open the Windows Control Panel (set View by to Small icons). Launch Communication Settings. Once open, select Access points on the left. Expand S7ONLINE and verify it is assigned to the Machine Control adapter (e.g., Intel(R) Ethernet Controller I226-V. TCPIP.AUTO. 1).
4

Ping the Siemens NCU

Turn the machine on. Open Command Prompt and ping the Siemens NCU IP address. A healthy network path will respond in < 5ms.
5

Verify S-Proxy & Advanced Firewall

Open services.msc, verify S-Proxy is Running. If the NCU pings successfully but S-Proxy fails, check that Windows Firewall is configured to allow S-Proxy traffic, Siemens S7 discovery (UDP), and ISO-on-TCP (TCP port 102).

Protocol 2: Windows Power & Adapter Optimization

Windows energy-saving features can inadvertently interrupt the continuous network "heartbeat" required by TarusNC. These settings must be disabled to ensure S-Proxy stability.

1

Set Power Plan to High Performance

Navigate to Control Panel > All Control Panel Items > Power Options. Select High Performance. This favors performance and prevents deep idle states.
2

Disable Sleep and Display Shutoff

Click Change plan settings next to High performance. Set Turn off the display to Never and Put the computer to sleep to Never.
3

Advanced Power Settings: Hard Disk

Click Change advanced power settings. Expand Hard disk > Turn off hard disk after. Change the Setting (Minutes) to 0 (Never). Click Apply.
4

Disable Network Adapter Power Management

Open Network Connections. Right-click the Machine Control adapter > Properties > Configure. Go to the Power Management tab. UNCHECK "Allow the computer to turn off this device to save power" and "Only allow a magic packet to wake the computer".
5

Disable Energy Efficient Ethernet (EEE)

In the same adapter configuration window, go to the Advanced tab. Scroll down the Property list to find Energy Efficient Ethernet. Change the Value to Off. Click OK and test S-Proxy stability.

Protocol 3: RF Interference & Wireless Mapping

If the physical cables, IPs, and Power Settings are correct, dropped communications may be caused by EMI noise (power cables routed with network lines) or heavy Wi-Fi traffic. If using wireless Hirschmann APs, map the network.

Purpose

This procedure provides technicians with the correct method for clearing the NC and PLC memory, restoring machine archives, and performing firmware recovery on a Siemens SINUMERIK 840D control. Following this procedure before attempting firmware recovery can prevent unnecessary software installations and reduce machine downtime.

Required Equipment

  • Engineering laptop
  • Siemens VNC Viewer
  • Siemens Boot Stick (correct firmware version)
  • Latest machine archive/backup
  • Ethernet connection to the NCU

Procedure 1 – NC & PLC Reset

1

Verify Startup

Power on the machine. Observe the NC 7-segment LED display. During a normal startup sequence, the display should cycle through several values before stopping at: 6
2

Set Initial Dial Positions

Set the rotary switches to the following positions, then reboot the control:
Device Position
NC Dial 1
PLC Dial 3
3

Switch NC to Normal Mode

After the controller finishes booting, rotate the NC Dial from 1 to 0. Verify the following LED status:
Indicator Status
READY Flashing Green
STOP Flashing Orange
SF Solid Red
4

Clear the PLC

Starting with the PLC dial at 3, perform the following sequence:

3 → 2 → 3 → 2

Leave the selector in Position 2.
5

Verify PLC Reset

The controller should now display:
Indicator Status
READY Flashing Green
STOP Solid Orange
SF OFF
7-Segment Display 6
6

Complete the Reset

Rotate the PLC Dial to 0. A successful reset is indicated by:
Indicator Status
READY Solid Green
RUN Solid Green
At this point, both the NC and PLC have been successfully cleared.

Procedure 2 – Restore the Machine Archive

Once the reset is complete:
  • Load the latest machine archive.
  • Restore all machine data.
  • Verify that the archive loads without errors.
  • Reference the machine if required.
Test and verify the following before returning the machine to service:
  • Axis travel
  • Machine limits
  • Home positions
  • Machine functions

Important Note

Always perform the NC/PLC Reset Procedure before attempting a firmware update. In many cases, the reset procedure restores normal operation without requiring firmware installation.

Procedure 3 – Firmware Recovery

Only perform this procedure if the standard reset fails.

Step 1 – Prepare the Control

Connect the engineering laptop to NCU. Insert the Siemens boot stick into the NCU USB port. The control should automatically enter Boot Mode. (Note: No rotary switch changes should be required.)

Step 2 – Open VNC Viewer

Launch Siemens VNC Viewer. After connecting, the screen may initially appear black. Select Refresh in the upper-left corner. The NCU service interface should appear.

Step 3 – Modify NCU Settings

Select: Modify NCU Settings. Perform a Clear or Factory Reset on each of the following: Drives, HMI, PLC, NCU. Allow each process to be completed before proceeding.

Step 4 – Update Firmware

Open: Update Firmware. Select: Install Firmware from Boot Stick. Choose: No Recovery. Allow the firmware installation to be completed without interruption. Do not remove power or disconnect the boot stick during the installation.

Step 5 – Restore the Machine

After the firmware update: Repeat the NC & PLC Reset Procedure. Restore the latest machine archive. Reference the machine. Verify Drives, Axis motion, Limits, and PLC operation. Return the machine to production only after all verification checks have been successfully completed.

Purpose

This procedure outlines the correct process for creating a machine archive in Operate. Archives should always be created before and after making changes to a machine. Maintaining these backups allows technicians to compare machine configurations, restore previous settings if necessary, and improve troubleshooting efficiency.

Required Equipment

  • Personal USB flash drive

Procedure

1 Open the Main Menu

From the Operate screen, select the M icon located in the upper-right corner of the display.

2 Access the Setup Menu

Select Setup from the Main Menu.

3 Navigate to Page 2

Once in the Setup menu, navigate to Page 2 using the expansion arrow.

4 Open the Archive Utility

Select Take an Archive. This option is located in the bottom-left corner of Page 2.

5 Configure the Archive

When the Archive screen appears:

• Verify and make sure that you click the option to Generate Archive and All Data of This Machine.

• Verify that all available component checkboxes (NCK, PLC, Drives, etc.) are selected. Selecting all options ensures the archive contains the complete machine configuration, making future comparisons and restorations possible.

6 Name the Archive

Enter a descriptive archive name using a consistent naming convention. Using a consistent naming convention makes archives easier to locate and identify.
Before Changes Customer_Machine_Before_Date Example: Ford_2021_Before_7-14-26
After Changes Customer_Machine_After_Date Example: Ford_2021_After_7-14-26

7 Select the Save Location

Select your personal USB flash drive as the archive storage location.

8 Start the Archive

Verify the archive name and storage location. Select OK in the bottom-right corner of the screen to begin the archive process.

Archive Process Rules

  • Progress bars will begin filling until they reach 100%.
  • Do not power off the machine.
  • Do not remove the USB drive.
  • Do not press Cancel.
  • Interrupting the archive process may result in an incomplete or unusable archive.
  • Remove the USB drive only after the confirmation message appears indicating the archive was completed without errors.

Expected: PLC Sign of Life Errors

While the archive is being created, the system may display "PLC Sign of Life" errors at the top of the screen.

This behavior is expected. These messages occur because the system performs a PO Reset during the archive process and do not indicate a machine fault. Do not be alarmed.

Best Practice Standard

Always create both a BEFORE and an AFTER archive whenever machine changes are made. Maintaining both archives provides several benefits:
  • Creates a complete backup before modifications are made.
  • Documents the machine configuration after repairs or programming changes.
  • Allows quick restoration if unexpected issues occur.
  • Simplifies troubleshooting by enabling side-by-side comparisons.
  • Supports consistent maintenance and service documentation.

First, we need to unhide the Siemens Control (Sinumerik Operate) so that it is visible on the PC’s desktop*.

*If Sinumerik Operate is already visible, you can skip this page.

Navigate to Config Folder

C:\Program Files (x86)\Siemens\MotionControl\siemens\sinumerik\hmi\cfg
2

Modify Filenames

First, select the file named “systemconfiguration” and add the text “ – hide” to its name. Next, select the other file named “systemconfiguration - show” and delete the “ – show” from the filename. Ensure that there are no spaces at the end. The filename must be exact for the Siemens control to open properly.

3

Verify Final Filenames

Your filenames should look like this when you are ready to open the Siemens control, Sinumerik Operate…

Operate will automatically open if SProxy or TarusNC is opened.

4

Open Operate Menu

In Sinumerik Operate, click the Menu button at the top right of the window to open the menu selection. This Button will reflect what Menu you are currently in.

5

Navigate to Setup

Navigate to the “Setup” Menu to access the NC and Drive parameters.

6

Open Machine Data

From here, you will need to navigate to “Mach. Data”. If the bottom row of buttons on the control appears different than this picture, be sure you are on the right menu page.

7

Open Drive Parameters

Once in the Machine Data menu, click on the “Drive parameter” button.

8

Select the Target Axis

In the Drive parameter menu, ensure that you are looking at the correct axis/drive. In this case, we want to navigate to “AX6: C1”. You can change which drive you are looking at with the “Drive +” and “Drive –“ buttons, or by pressing the “Select a drive” button.

9

Locate Parameter 1990

Scroll down until you find parameter “p1990”. Alternatively, you can use the “Search” function and type in “1990”.

10

Set Parameter 1990

P1990 will be 0 by default. Change this parameter to a 1. You will see an alarm message pop up stating that the axis is ready for commutation determination, this is normal. While p1990 = 1, the commutation check will automatically be performed the next time drives are enabled.

11

Perform Commutation Check

Next, enable the drives, either through TarusNC or SProxy. You should hear a quick audible buzz come from the motor when the commutation check is performed and, if successful, p1990 will revert to a 0.

A new alarm message will appear, stating that the drive needs to be saved. Ignore this for now.

If the check fails:

You will likely see alarm 207995 - Drive: Pole position identification not successful, cause X. The “cause” number will determine the issue.

  • Cause 3: Simply means that the measured change in the commutation angle was larger than expected and needs to be measured again. Usually when this happens you can clear the alarm and the check will run fine on the next attempt.
  • Cause 1, 2, 4X or 5: Typically only occurs with a wiring issue.
12

Review Angular Difference

Just above p1990, parameter “r1984” will display the difference between your last commutation offset and the current one you just measured.

We want to perform our commutation angle measurement 3-4 times to ensure that we have a good measurement. The first time you perform the measurement, p1984 will likely be a large number, but on subsequent measurements you should see that number approach 0.00° degrees.

Keep performing these checks (by changing p1990 = 1 and enabling the drives) until r1984 is within ±4.00° degrees. The closer to 0, the better.

13

Save Your Changes

Once you have a good commutation angle, you will need to save your changes by clicking the “Save / Reset” button on the right side of the window. Next, click “Save”, then “Drive System”.

14

Verify Physical Movement

Before Moving the Axis, disable the drives and turn the head by hand to both hard stops. Ensure that the axis can freely move at least 180.5° degrees in both directions.

Click on the wrench icon at the top right of the window, then click the “Machine” button at the bottom left.

From the Machine Screen, you can monitor the C Axis position by scrolling down in the position window.

Connecting to the Drive

Connect to the drive via RS232 communication cable. This cable has a DB9 on one end and a S-video type connector on the other. The S-video type connector is what plugs into the drive. The DB9 plugs into a PC.

Since most new PC's do not have a RS232 port on them anymore you will have to use a USB to RS232 adapter to communicate.

Software Configuration

Once the physical connection is made you will now open the drive software: Indraworks Ds or Indraworks Engineering.

To log onto the drive you must select the type of connection you will make, which in this case will be via RS232. (both Ds and Engineering uses both RS232 and ethernet communication).

The com port you will select will depend on what the PC has assigned to the USB to RS232 adapter. You can use the Windows Device Manager to check the com port assignment and baud rate.

Resetting the Drive

1

Diagnose the Fault First

Before resetting the drive you must understand why you are getting this fault. Just resetting the drive does not always fix the problem. Drive error codes will be displayed both on the drive and in the drive software. You can look these errors up in the drive help supplied on the PC.
2

Switch to Parameter Mode (PM)

To reset the drive you must first put the drive into parameter mode. You do this by clicking on the PM that is green in the upper middle of the drive page.

Clear Errors & Return to OM

Once you are in PM (parameter mode) you can click the Clear error icon. This icon is located just to the left of the PM and is a red circle with an X and a check mark in the middle of it. This will clear all errors.

Now that your error is cleared you must return to OM (operating mode). Again this is located just to the right of the PM and will be green. Click on the OM and the drive will attempt to change into operating mode. If the drive errors again you have bigger problems that need to be addressed.

Commutation of the Motor

1
Once you have the drive in OM most of our motors need to have the commutation offset found.
2
To do this you need to go into: Drive control > Motor Control > Commutation settings.
3
In the commutation setting window you can find the offset by clicking on Determine Commutation Offset.

(Note: The drives must be in Ab to work or it will fault).
4
You can now continue with normal operation.
Document Type Training / Standard Work Instruction
Equipment Schneeberger Encoder
Task Encoder Battery Replacement

1. Purpose

This standard work instruction provides the required steps for identifying a Schneeberger encoder battery issue, replacing the encoder batteries, and documenting the service condition for training and maintenance reference.

3. Required Tools and Materials

  • • Replacement encoder battery
  • • Allen keys for rear cap screws & bird cage screws
  • • Digital multimeter capable of measuring DC voltage
  • • Marker or label for recording the replacement date
  • • Service issue notes or maintenance log

2. Safety and Important Requirements

  • The machine must always remain powered on during the battery replacement process.
  • Use caution when removing covers and small fasteners to prevent damage or lost hardware.
  • Follow all site-specific safety, lockout, and maintenance procedures as required before beginning work.

4. Procedure

1
Review the operator diagnostics screen.
Confirm the error displayed. The issue will most likely appear as an encoder error and may be shown on the Z or Y axis. Depending on the application, it may also appear on the X axis.
2
Inspect the encoder indicator.
Remove the bird cage cover and check the light indicator on the Schneeberger encoder.
3
Evaluate the light combination.
Review the indicator pattern displayed by the encoder and determine whether the battery requires replacement.
4
Access the encoder.
Locate the encoder in question and remove the rear cap. The rear cap is secured with four small Allen screws. Remove the cap carefully. Important: The machine must always remain powered on during battery replacement.
5
Replace the batteries.
After the rear cap is removed, replace the batteries. Before installation, mark the replacement date on the new battery.
6
Verify and document the old battery condition.
Check the voltage of the removed battery and record the DC voltage in the service issue notes.
Note: If additional troubleshooting is required, review the encoder indicator status, confirm the axis associated with the alarm, and verify that the battery replacement was completed while the machine remained powered on.
